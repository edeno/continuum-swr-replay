# Content refit comparison: count response vs per-event fraction response

Generated by `scripts/qa/compare_fits.py --content`. The content ladders changed RESPONSE, not specification: the per-timebin count (`arm_count_hard` / `patch_count_hard`) was replaced by the per-event allocation fraction (`arm_fraction` / `patch_fraction`), so every event contributes one observation of unit mass, and the fits now also carry event-clustered standard errors.

**Read the scales, not just the numbers.** Coefficients are comparable term for term. Standard errors are not: the *before* column is the model SE of a design that treated a median ~32 autocorrelated timebins per event as independent draws; the *after* column the aggregation reads is the event-clustered sandwich. Likelihood-scale quantities (AIC, ΔAIC, BIC) are stated per timebin before and per event (quasi-likelihood) after, so the before/after ΔAIC columns are **different scales** and must never be differenced or read as an effect change.
