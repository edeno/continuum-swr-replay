# Documentation index

Every documentation artifact has **one home by type**. This index states the scheme so
it stops drifting; add new docs to the matching home.

## Where each doc TYPE lives

| type | home | what it is |
|---|---|---|
| catalog | `docs/models_table.md` | every regression model in R notation (mirrors `model_specs.py`) |
| definitions | `docs/covariate_dictionary.md`, `docs/behavior_model_covariates.md` | canonical covariate definitions; the `qvals_table` data dictionary |
| reference (models) | `docs/behavior_models.md` | the SpatialBanditTask generative models (Beta-Bernoulli, HMM, Q-learners) that produce the behavioral covariates |
| methods and results | `docs/rate_models.md` | how the two event-rate model families work and are checked, with the fits and comparisons that shaped them; the values it quotes are generated markers filled from `paper/reported/` |
| results | `paper/reported/questions.md` (generated) | every reported value, under the question it answers, in the paper's outline |
| reference | `docs/task_description.md`, `docs/cached_trials_for_testing.md`, `docs/known_issues/` | task/data background |
| cohort | `docs/epoch_register.md` | which run epochs are analysed, and the reason for every other one (mirrors `data_loaders/epoch_register.py`) |
| **design spec** (scientific/methodological) | **`docs/design/`** | analysis designs — human-discoverable for collaborators/reviewers |
| history | `docs/history/` | where moved code and data went, and the dated audits the docs once cited; not current instruction |
| implementation plan (agent process) | `.claude/docs/plans/` | phased execution plans |
| review (code/methods output) | `.claude/docs/reviews/` | point-in-time review reports, and the dated audits (before/after refit comparisons, regeneration and parity checks). A decision, validation or limitation a reader needs is copied into `docs/design/` or `docs/known_issues/`, which may link back to the audit as its dated source |
| exploratory notes + figures | `.claude/research/` | scratch analyses; `*_outputs/` figures. Untracked, so no doc or docstring cites it as evidence: a finding a reader needs is written into `docs/design/` or `docs/known_issues/` as a dated measurement |
| code map (generated) | `docs/regression_pipeline_map.md` | every pipeline module and the public symbols it defines, by stage |
| model spec (code) | `src/continuum_swr_replay/analysis/replay_models/model_specs.py` | single source of truth for all model ladders |

Rule of thumb: **published/scientific → `docs/`; agent-process/scratch → `.claude/`.**

## Code layout

`src/continuum_swr_replay/` is layered. Code may import from its own layer and the
layers below it, never from a layer above:

1. **Foundation**: `columns.py`, `data_loaders/`, `data_types.py`, `decoding/`, `intervals.py`,
   `parameters.py`, `paths.py`, `runs/`, `tables/`. A foundation module imports only
   other foundation modules. `analysis/constants.py` imports only the foundation;
   `analysis/shared_statistics.py` holds the statistics that know nothing of the task
   (the signed-rank test, the Benjamini-Hochberg correction, the animal-balanced
   summary over sessions, the nested bootstrap) and imports nothing from the package.
2. **`analysis/`**: one package per question, in pipeline order. Each imports only
   the packages before it in the table below (and the foundation, `constants` and
   `shared_statistics`). `event_definition/` imports no other analysis package. In
   Part 1 and Part 2 the order is `event_definition` → `decode_quality` → `detection`
   → `event_evidence` → `event_properties` and `detector_comparison` (the last two
   do not import each other); none of them imports `behavior/`, `event_tables/`,
   `replay_models/`, `pfc/` or `contfrag/`. `behavior/` → `event_tables/` →
   `replay_models/` import in that order. No `analysis/` code imports
   `visualization/` or `reported/`.
3. **`visualization/`** and **`reported/`** (the summary builders), side by side, then
   **`scripts/`** on top. `reported/` imports only the foundation and `analysis/` (it
   names and describes the statistics that `analysis/` computes). Nothing in `src/`
   imports `scripts/`.

There are no package cycles. `tests/repository/test_import_layering.py` enforces every
rule above, and keeps `data_loaders/` from importing `analysis/` and the covariate
builders from importing `replay_models/model_specs.py`. It has no allowlist: any
violation fails.

| Stage | Package (`analysis/`) | Owns | Does not own |
|---|---|---|---|
| Rule | `event_definition/` | analysed time and excluded time, immobility, the non-local event rule (`nonlocal_event_rule.py`), the canonical SWR source, the decode masks, the classified event table and the cohorts | any detector or statistic |
| Find | `detection/` | the algorithms that produce inventories: the SWR and Carey detectors, rule R-T, the artifact detector, the memoryless sequence detector, the paper's non-local detector applied to a decode (`nonlocal_events.py`) | which inventory is canonical; comparing inventories |
| Compare | `detector_comparison/` | the inventories brought onto one schema and compared on the same recordings: overlap, exposure, counts, event features, held-out evidence | running a detector |
| Check | `decode_quality/` | whether the decode is trustworthy: decoding error, state fractions, calibration, raw-data flags, posterior summaries | reading a saved decode (`decoding/results.py`) |
| Check | `event_evidence/` | whether the events are real: held-out spike evidence per event and per decoder state | event properties |
| Describe | `event_properties/` | what the events are like and how SWR and non-SWR events differ: event statistics, the property contrasts, class or continuum, gamma, theta, brain-state references, content occupancy | the behavioral models |
| Task | `behavior/` | what the animal did and what the behavioral model says: covariates, design constants, track lookups | the tables and the models |
| Join | `event_tables/` | the canonical event, arm, patch, stop and time-bin tables and their contracts | fitting |
| Model | `replay_models/` | the Part 3 rate, content, coupling and choice models and the fitting machinery | the tables |
| Model | `pfc/` | the mPFC and OFC unit analyses (Part 4) | the hippocampal event rule |
| Side pipeline | `contfrag/` | the Continuous-Fragmented classifier analysis and its tables | the paper's event definition |

| Paper part | Packages | Scripts | Summary |
|---|---|---|---|
| Part 1, detection | `detection`, `detector_comparison` | `scripts/detection/`, `scripts/detector_comparison/` | `paper/reported/detection.json` |
| Part 2, events | `decode_quality`, `event_evidence`, `event_properties` | `scripts/decoding/` (decoder quality), `scripts/event_evidence/`, `scripts/event_properties/` | `paper/reported/events.json` |
| Part 3, behavior | `behavior`, `event_tables`, `replay_models` | `scripts/behavior/`, `scripts/tables/`, `scripts/replay_models/` | `paper/reported/behavior.json` |
| Part 4, mPFC | `pfc` | `scripts/pfc/` | `paper/reported/mpfc.json` |

The summary names follow the paper's parts, not the package names: `reported/events.py`
builds Part 2's summary from three packages, and `reported/detection.py` Part 1's from
two.

Inside `behavior/`, the top-level modules do not import `covariates/`; inside
`replay_models/`, `rate/`, `content/`, `coupling/` and `choice/` do not import each
other, and the top-level machinery (`model_specs.py`, `per_bin_design.py`, the
fitters, the cohort, timing and contrast modules) imports none of them. The layering
test checks these too.

Where each moved, renamed or split module went (2026-10 and 2026-11) is recorded in
[history/2026-module-moves.md](history/2026-module-moves.md).

## Figure outputs

- **`paper/figures/<topic>/`** — publication figures only, in topic subdirs (main-text
  `figure0N/`, `supp_*`, and analysis topics like `rate/`, `reality/`, `quality_metrics/`).
  No loose files at the top level. Generated by `scripts/figures/*` and the `scripts/*/plot_*.py`.
  Scripts spell the directory as `continuum_swr_replay.paths.figure_dir(topic)`, which sits
  beside the data root, so a run on another root (`CSR_PROCESSED_DATA_DIR`, e.g. a
  `run_refits` staging run) writes its figures there, not over the paper's.
- **`.claude/research/*_outputs/`** — exploratory / scratch figures (from `scripts/exploratory/_*.py`),
  not results-of-record.

## Where results live

Three tiers:

1. **Result DATA** (`.parquet`/`.pkl`/`.nc`, gitignored) under the data root,
   `paths.processed_data_dir()` (`$CSR_PROCESSED_DATA_DIR` when set, else the checkout's
   `Processed-Data/`). Code spells each location through `continuum_swr_replay.paths`
   (`replay_content_dir()`, `model_dir(key, root)`, `table_path(name, root)`), not
   inline. How the tables are stored and read is in
   [data-lineage.md](data-lineage.md).

   The canonical tables (events, event-arms, event-patches, sequences, stops) are built
   by `scripts/tables/prepare_replay_content_data.py`, and `qvals_table` by
   `scripts/behavior/build_qvals_table.py`, all at the root of `replay_content/`. The
   fits beside them:

   | dir | producer | holds |
   |---|---|---|
   | `models_per_bin_rate/` | `scripts/replay_models/rate/fit_per_bin_rate_models.py`, `fit_swr_contrast_rate.py`, `fit_uncertainty_rate.py`, `fit_cross_history_rate.py` | the per-bin rate fits: `all_models.pkl` (Family-B ladder), `swr_contrast_rate.pkl`, `uncertainty_rate.pkl`, `cross_history_models.pkl`; plus three exploratory one-offs nothing supported reads (`contingency_table.pkl`, `contingency_csv_alpha.json`, `covariate_ranking.pkl`) |

   | `models_per_stop_rate/` | `scripts/replay_models/rate/fit_per_stop_rate_models.py` | Family-A per-stop ladder |
   | `models/`, `models_patch/` | `scripts/replay_models/content/fit_replay_content_models.py` (arm / patch) | the default content ladders — arm `M0`, `M0a`, `M1`–`M6`; patch `P0`–`P3` — on the at-well events, plus the opt-in value/uncertainty rungs (`Mv`, `Mu`, `Mvu`, `Pv`) when named with `--models` |

   `<run>_term_diagnostics.csv`.
